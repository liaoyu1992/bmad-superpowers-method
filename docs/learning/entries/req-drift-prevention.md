# 需求漂移防范清单

> 触发条件：需求漂移 + 多了/少了
> 创建时间：2026-08-21

## 需求多了（Spec 有原文没提及的功能）

### 常见原因
1. AI"顺便"实现了需求文档中没有的功能
2. AI 基于"常见模式"推测了需求文档没有的功能
3. AI 把某个技术实现细节当作需求写入了 Spec

### 防范措施
1. **防线 A**：每条 Spec 必须标注原文出处
2. **防线 B**：反向校验时逐条检查 Spec 是否有原文依据
3. **YAGNI 原则**：在提示词中明确强调"禁止添加 Spec 未提及的功能"
4. **交叉审问**：防线 C 检查"范围溢出"

## 需求少了（原文有但 Spec 没覆盖）

### 常见原因
1. AI 遗漏了 PRD 中的某个段落
2. AI 把多个需求合并成一个，丢失了细节
3. PRD 中的隐含需求被忽略
4. PDF/Word 转换时丢失了部分内容

### 防范措施
1. **防线 B**：反向校验时逐条扫描原文每个段落
2. **转换验证**：阶段零转换后检查是否有内容丢失
3. **段落级比对**：不是只看标题，要逐段扫描
4. **交叉审问**：防线 C 检查"范围缺失"

## 平台串台

### 常见原因
1. 混合 PRD 中 APP 专属功能被误放 PC 分区
2. 后端 API 被误归到前端分区
3. 不确定平台归属时擅自归类

### 防范措施
1. **防线 C**：交叉审问检查平台归属
2. **不确定时列入"待确认"**：不要擅自归类
3. **平台分区编号**：REQ-BE- / REQ-PC- / REQ-APP- / REQ-XP- 独立编号
