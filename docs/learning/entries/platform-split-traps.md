# 平台拆分常见陷阱

> 触发条件：需求分析 + 多平台
> 创建时间：2026-08-21

## 常见陷阱

### 1. 后端 API 误归前端

**现象**：PRD 描述了一个"用户列表"功能，AI 把整个需求归到了 PC 分区。
**问题**：实际上"用户列表"涉及后端 API + PC 页面 + APP 页面，应拆分到各自平台。
**正确做法**：
- 后端分区列 API 定义和数据模型
- PC 分区列 PC 页面消费行为
- APP 分区列 APP 页面消费行为
- 如果 API 同时服务多个前端，后端需求中标注"服务于 PC + APP"

### 2. 跨平台功能漏标

**现象**：登录功能同时涉及 PC 和 APP，但只在 PC 分区列了。
**问题**：APP 分区漏了登录的前端行为。
**正确做法**：跨平台功能使用 REQ-XP- 编号，同时在各平台分区列出前端消费行为。

### 3. 平台术语不统一

**现象**：PRD 中叫"工单"，PC 分区写成"任务单"，APP 分区写成"工单"。
**正确做法**：术语必须与原文一致。交叉审问（防线 C）会检查这一点。

### 4. 小程序需求误归 APP

**现象**：微信小程序需求被归到了 APP 分区。
**正确做法**：小程序和 APP 是不同平台，应该独立分区（REQ-MP- 编号）。
