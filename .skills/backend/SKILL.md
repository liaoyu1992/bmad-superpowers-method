# backend — 后端 TDD 工程师

> 阶段四技能。按 TDD 流程实现后端功能。

## 执行流程（每个 Step 严格按此顺序）

1. **读取计划**：加载 `docs/plans/plan-NNN-backend-*.md`（只为实施范围内的平台执行）
2. **读取 Spec**：加载 `tech-spec.md` 和 `requirements.md` 中对应章节
3. **检查平台筛选**：如果 `requirements.md` 有平台筛选，只执行实施范围内的后端计划
4. **依赖检查（codegraph）**：如果要修改已有函数/接口/数据模型，先用 codegraph 查看谁调用了它，评估影响面，避免「改 A 炸 B」
   - 调用前提：IDE 已安装 codegraph MCP 插件
   - 如果是新建文件/函数，跳过此步
5. **定义测试用例**：根据 AC 编写测试用例清单
6. **写测试代码**：先写自动化测试
7. **运行测试 → 红灯**：确认测试失败
8. **写实现代码**：满足所有最佳实践
9. **运行测试 → 绿灯**：确认测试通过
10. **重构**：优化代码质量，保持测试通过
11. **Mental Model Execution**：追踪 2-3 个场景
12. **质量门禁**：执行 6 道关卡检查
13. **更新计划状态**：将 plan 中对应 Step 标记为 [x] 已完成
14. **自动接力**：当前 Step 完成后自动开始下一个 Step

## 代码要求

- **Spec 对齐**：每个文件/函数注释标注对应的 Spec 章节号和 REQ 编号
- **禁止**：占位代码、TODO、未经测试的代码路径
- **错误处理**：快速失败，不静默吞错
- **事务**：所有写操作必须有事务包裹
- **Null 安全**：所有外部输入必须做空值检查

## TDD 红灯验证

写完测试后必须运行并确认失败。如果测试直接通过，说明：
- 测试写错了（检查断言逻辑）
- 或代码已存在（确认是否重复实现）

**禁止跳过红灯阶段。**

## 质量门禁（每完成一个功能模块）

执行 `/quality-gate` 检查 6 道关卡：
1. **编译**：`npm run build` 或 `tsc --noEmit`
2. **Null 安全**：检查所有外部输入
3. **API 契约**：接口定义与 tech-spec 逐字段对齐
4. **事务**：所有写操作有事务
5. **并发**：无竞态条件
6. **错误处理**：无未捕获异常
