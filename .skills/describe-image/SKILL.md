# describe-image — 多模态图片识别桥接

> 借鉴 BOSS /boss-describe-image 机制。给不支持多模态的模型装上"眼睛"。

## 核心思想

当用户上传/粘贴图片时，文本模型无法直接"看到"图片。
本技能自动调用支持多模态的模型（如 GLM-4V-Flash），将图片转为结构化文字描述，
再把描述文本交给主模型继续原任务。

## 自动触发条件

以下情况自动触发：
- 用户消息中出现图片（上传/粘贴截图）
- 工具产生截图产物
- 用户说"看这张图"、"按设计图写页面"、"这个报错怎么修"
- UI 走查 / 设计还原

## 执行流程

```
① 检测到图片
    ↓
② 图片转 base64（限制单图 < 5MB，≤ 6000×6000）
    ↓
③ 调用多模态模型解析（按 8 维度结构化描述）
    ↓
④ 描述文本进入主模型上下文
    ↓
⑤ 主模型继续原任务（"按设计图写页面"等）
```

## 8 维度结构化描述

多模态模型按以下维度描述图片：

```json
{
  "类型": "设计稿 / 截图 / 报错界面 / 照片 / 图表",
  "布局": "整体布局结构（如：顶部导航 + 左侧菜单 + 右侧内容区）",
  "元素": "关键 UI 元素列表（按钮、输入框、表格、卡片等）",
  "文字": "图片中的所有文字内容（OCR）",
  "配色": "主色/辅助色/背景色（含 HEX 值）",
  "状态": "元素状态（hover/active/disabled/loading 等）",
  "交互": "可交互元素的操作行为（点击/输入/选择等）",
  "风格": "设计风格（扁平/拟物/玻璃态等）"
}
```

## 多模态模型配置

```yaml
# 推荐配置（免费方案）
model: glm-4v-flash
base_url: https://open.bigmodel.cn/api/paas/v4
api_key: 从环境变量 GLM_API_KEY 读取（禁止硬编码）

# 备选方案
# model: gpt-4o-mini（OpenAI，需付费）
# model: qwen-vl-plus（通义千问，有免费额度）
```

## 使用场景

| 场景 | 描述 |
|------|------|
| 设计还原 | 用户上传设计稿 → 描述 → 按"描述生成前端页面" |
| 报错诊断 | 用户粘贴报错截图 → 描述 → 分析错误原因 |
| UI 走查 | 截图当前页面 → 描述 → 对比设计 Spec 找差异 |
| 文档识别 | 上传 Word/PDF 截图 → OCR 提取文字 → 转为 Markdown |

## 安全要求

- API Key 从环境变量读取，**禁止硬编码**
- 图片 base64 编码后传输，不落盘
- 不将图片内容发送到非授权的第三方服务

## 与上下游技能衔接

| 衔接方向 | 说明 |
|----------|------|
| → `frontend` | 设计稿描述 → 按描述生成前端页面 |
| → `troubleshoot` | 报错截图描述 → 分析错误原因 |
| → `designer` | 截图 → 对比 design-spec 找差异 |
| → `convert-documents` | 图片 OCR → 转为 Markdown |
