# research — 技术调研

> 借鉴 BOSS /boss-research 机制。系统化技术调研。

## 执行步骤

### 步骤 1：明确调研目标

- 要调研什么技术/方案？
- 调研目的是什么？（选型、可行性、学习）
- 评估维度有哪些？（性能、成本、社区、学习曲线等）

### 步骤 2：收集资料

通过以下渠道收集：
- 官方文档
- GitHub 仓库（star 数、活跃度、issue 处理速度）
- 技术博客和评测
- 社区讨论（Reddit、Stack Overflow、掘金等）
- 真实项目使用案例

### 步骤 3：对比分析

生成对比矩阵：

```markdown
## 对比矩阵

| 维度 | 方案 A | 方案 B | 方案 C |
|------|--------|--------|--------|
| 性能 | ⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| 生态 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐ |
| 学习曲线 | ⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐ |
| 维护成本 | 低 | 中 | 高 |
| 社区活跃度 | 高 | 高 | 中 |
| 文档质量 | 优秀 | 良好 | 一般 |
```

### 步骤 4：风险评估

每个方案的风险点：

```markdown
## 方案 A 风险
- **风险 1**：[描述] → 缓解措施：[...]
- **风险 2**：[描述] → 缓解措施：[...]
```

### 步骤 5：选型建议

输出到 `docs/reports/research-NNN.md`：

```markdown
# 技术调研报告 research-001

## 调研主题
[主题]

## 调研结论
推荐方案 A，理由：
1. ...
2. ...

## 妥协点
- 接受方案 A 的 XX 劣势，因为 ...
```

### 步骤 6：加载经验库

- 读取 `docs/learning/LEARNING.md` 索引表
- 匹配"技术调研"或"选型"触发条件
- 如有新经验，追加到 LEARNING.md 并写入 `docs/learning/entries/`

## MCP 工具协作

调研过程中可使用以下 MCP 工具辅助：
- **firecrawl / anysearch**：抓取官方文档、技术博客、社区讨论
- **context7**：查询第三方库的最新文档和 API
- **upgrade-mcp**：扫描当前项目依赖版本，对比 GitHub 趋势，生成升级建议报告
  - 触发场景：用户说"检查升级"、"依赖是否过时"、"upgrade-mcp"
  - 产出：`docs/reports/upgrade-scan-NNN.md`，包含过时依赖清单 + 推荐升级版本 + 风险评估
  - **自动触发**：用户可配置定期触发（如每周一），通过 IDE 的定时任务功能实现，扫描后自动生成报告并写入经验库
  - **历史会话缺陷扫描**：扫描 `docs/learning/entries/` 中的历史经验，检查是否有已修复的缺陷模式仍在出现，在报告中包含"历史缺陷复现统计"
  - 调用前提：IDE 已安装 upgrade-mcp MCP 插件

## 使用场景

| 场景 | 示例 |

| 框架选型 | "React vs Vue vs Svelte，给个建议" |

| 第三方服务 | "用阿里云 OSS 还是自建 MinIO" |
| 依赖升级 | "检查项目依赖是否需要升级" |
