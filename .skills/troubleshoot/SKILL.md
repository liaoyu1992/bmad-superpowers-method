# troubleshoot — 故障排查

> 借鉴 BOSS /boss-troubleshoot 机制。系统化排查问题。

## 排查流程

```
现象描述 → 复现问题 → 查日志 → 查数据 → 定位源码 → 根因分析 → 修复方案
```

### 步骤 1：现象描述

收集问题描述：
- 什么操作触发了问题？
- 预期结果 vs 实际结果？
- 什么环境？（开发/测试/生产）
- 什么时候开始出现？
- 影响范围？

### 步骤 2：复现问题

- 能否稳定复现？
- 复现步骤是什么？
- 是否与特定数据/用户/时间有关？

**MCP 工具协作**：如果是前端问题，可使用 **playwright** MCP 工具复现：
- 用 playwright 打开页面，按用户操作链路执行（导航 → 点击 → 填表）
- 抓取 console 日志、网络请求、截图作为证据
- 自动化复现，避免手动操作差异
- 调用前提：IDE 已安装 playwright MCP 插件

### 步骤 3：查日志

根据环境查找日志：
- 开发环境：控制台输出
- 测试环境：CI/CD 日志 + 应用日志
- 生产环境：日志系统（如 Loki/ELK）

重点查找：
- 异常堆栈（Exception/Error）
- 时间窗口内的 WARNING/ERROR
- 关联请求的 traceId/requestId

### 步骤 4：查数据

检查相关数据状态：
- 数据库记录是否符合预期？
- 是否有脏数据？
- 关联表的数据一致性？

**安全红线**：
- 生产数据库只读查询
- 禁止在生产环境执行写操作
- 查询结果最多 100 行，防止全表导出

### 步骤 5：定位源码

基于日志和数据线索，在源码中定位问题：
- 异常栈中的文件:行号
- 相关业务逻辑的代码路径
- `git log -S` 查看相关代码的变更历史

**MCP 工具协作**：当需要分析调用链路时，可调用 **codegraph** MCP 工具：
- 从异常栈的函数出发，追踪完整调用链
- 分析"谁调用了这个出问题的函数"，排查上游传参问题
- 调用前提：IDE 已安装 codegraph MCP 插件

### 步骤 6：根因分析

输出根因分析报告：

```markdown
# 故障排查报告 troubleshoot-001

## 问题描述
[现象描述]

## 根因
[根本原因，不是表面现象]

## 影响范围
[受影响的功能/用户/数据]

## 证据链
1. 日志证据：[日志原文 + 时间 + 服务]
2. 数据证据：[数据状态 + 查询 SQL]
3. 源码证据：[文件:行号 + 代码片段]

## 修复方案
- **临时方案**：[快速止血]
- **根本方案**：[彻底修复]

## 预防措施
- [如何避免再次发生]
```
